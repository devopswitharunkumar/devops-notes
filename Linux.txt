SSH (Secure Shell) :
-------------------------
SSH is a secure network protocol used to connect and manage remote servers over an encrypted network connection.
--> It allows developers and system administrators to log into a remote server's terminal to run commands and manage systems
--> It enables secure file-sharing mechanisms like SFTP (SSH File Transfer Protocol) and SCP (Secure Copy Protocol) 
--> It creates an encrypted "tunnel" to securely pass traffic from other applications across the network

Process :
------------
1)	ssh key-gen -f <filename> 							 --> it will generate the new public key and privatekey in particular loc in local based on laptop 				-f  --> File 
2)	ssh-rsa <publickey code> <laptopname> --> This line tells the server: Allow the owner of the matching private key to authenticate/login. 

We use ssh-rsa public keys for secure passwordless SSH authentication.
When SSH connection starts, the server verifies the matching private key before allowing access. It creates an encrypted tunnel so nobody can easily read the data.

ssh-rsa  --> it represents the SSH key and it indicates that the key was generated using the Rivest-Shamir-Adleman (RSA) algorithm
rsa used for secure key exchange, digital signatures, and authenticating connections across the internet

To Connect :  ssh username@Ec2-public-ip


Types :
---------
1)Password Authentication -----> using ssh username@ipaddress  --> prompt for password u have to enter 
2)SSH Key Authentication   ------> using ssh -i privatekey.pem ec2-user@<public ip>				-i --> Identity

3)	For 2nd step we will give a public key data in --> AWS console --> EC2 --> key pairs --> Actions --> import key pair --> give name and paste public key content in that --> save --> while creating EC2 select that imported key in key pair section --> if both public key and local private key matches then it will allow the connection 

SSH default  port is ---> 22

4)ssh -i <private key> <username@private ip address> 
--> is used to securely connect to a another remote server(like databases which has onlyprivate ip's ) using SSH key-based authentication instead of passwords from one remote server not from local

Step 1 —> SSH Client Starts 					--> Your laptop starts SSH programYour and reads your local private key
Step 2 —> Connection to Server 			--> connects to the target IP address -> 54.23.11.90 on prot - 22((default SSH port)) 
Step 3 —> Server Checks Public Key 	--> Before generating a challenge, your laptop sends its private key ID. The server looks inside its ~/.ssh/authorized_keys file to ensure that matching public key exists. 
Step 4 —> Server Sends Challenge 		--> If the server finds the key, it generates a random piece of text (a challenge), encrypts it using your public key, and sends it back to your laptop
Step 5 —> Private Key Verification  		--> my laptop use - mykey.pem (to generate encrypted response.) or Your laptop uses your secret privatekey.pem to decrypt the challenge and sends the unencrypted response back to the server
Step 6 —> Secure Session Created 		--> The server verifies your response matches. ✅ Authentication is successful, and you are granted terminal access

s --> Special Executable permissions. It is one type of permission :
---------------------------------------------------------------------------------------
It usually represents 
		1)SUID -> Set User ID				---> useful when u want temporary root previlages
		2)SGID -> Set Group ID			---> useful when u r creating a shared team folder 
		
--> When a file has an s in its permission string, it means a user running that file will temporarily gain the privileges of the file's owner or group, rather than running it with their own account privileges.

Where Does the s Appear?
The s replaces the standard execute (x) position in the ls -l permission string
1. SUID (s in the User section)	: The program runs with the privileges of the file owner.
	-rwsr-xr-x
2. SGID (s in the Group section)	:  The program runs with the privileges of the file group.
	-rwxr-s--x

Capital S vs. Lowercase s :
s 	-->  Means the execute permission (x) is also active     Ex : rws  --> rw + x + SUID
S	-->  Means the execute permission (x) is not active as special permissions do nothing without execution rights    	 Ex : rws  --> rw  + SUID


Real-World Example: 
The best example of SUID is the passwd command, which allows normal users to change their own passwords.

Ex :  -rwsr-xr-x 1 root root /usr/bin/passwd

Because of that s, when a normal user runs passwd, the system treats them as root for the split second it takes to update the password file.

ex : rwsr-xr-x
1) When another user executes file: process runs with file owner permissions(root permissions ) instead of current user permissions
		Set SUID: chmod u+s filename
2) Process runs with: file’s group permissions instead of user's primary group.
ex : chmod g+s project   --> ✅ all new files inherit directory group automatically.	
Set SGID: chmod g+s filename / chmod g+s dirname/

Using Numeric Mode : In this we get 4 numeric digits 
		1. 4 = SUID
		2. 2 = SGID

 Adding the -m option forces the system to automatically generate that directory and populate it with default configuration files (like .bashrc)

Creates the user account named bob.
Automatically creates the directory /home/bob.
Copies starter configuration files into /home/bob so the user has a working terminal profile upon their first login.

Dual Behavior: useradd vs. usermod
Depending on which command you are using, the -m option acts slightly differently

1. With useradd (Creating a user)
-m: Automatically creates the home directory.

2. With usermod (Modifying an existing user)
When changing an existing user's home folder path, -m is paired with -d to move their old files to the new location.

sudo usermod -d /new/home/path -m bob

Note :
If you prefer a tool that handles this automatically without needing to remember flags, use adduser instead of useradd. The adduser command is an interactive script that creates the home directory, sets the password, and creates the folder all in one step without needing the -m option.

When you run a command like kill -9 <pid>
your kill command doesn't touch the target program/process directly. Instead, it makes a system call to the operating system's kernel, saying: "Please deliver this signal to Process 1234." The kernel receives this request, finds the process in system memory, and forces it to react according to signal type.
The Linux Kernel is the entity that actually kills, pauses, or restarts the process.

Scenarios of handling :
------------------------------
Scenario 1 :
SIGKILL  and SIGSTOP  and SIGCONT  --> in this signal's kernel will do the things and The process has no say in the matter.

SIGKILL (Signal 9)		: The kernel immediately stops scheduling CPU time for the process, tears down its memory space, and destroys it. The process cannot block, catch, or ignore this.
SIGSTOP (Signal 19)	: The kernel instantly freezes the process in place. The process is paused and cannot execute any instructions until it receives a resume signal.

Scenario 2 :
For other signals, the kernel delivers a "tap on the shoulder" to the process. The process must stop what it is doing and execute a specific piece of code called a Signal Handler.
SIGTERM (Signal 15 - Default kill): The kernel tells the process to terminate. The process's signal handler catches this, allowing it to gracefully close open files, save database states, and clean up temporary files before shutting down.
SIGHUP (Signal 1 - Hangup/Restart): The kernel delivers the signal. Many background daemons (like web servers) write their signal handlers to respond to this by reloading their configuration files and restarting internal services without fully shutting down.

Process :  when i type --> sudo yum install nginx 
Step 1: Read the Repository File Locally
Before hitting the internet, yum reads the local text files in /etc/yum.repos.d/ to see which server it needs to talk to and If you are using the official NGINX repo, it opens a file like /etc/yum.repos.d/nginx.repo and reads a line that looks like this:baseurl=https://nginx.org/packages/centos/$releasever/$basearch/

/etc/yum.repos.d/ :  This directory contains text files ending in .repo (e.g., nginx.repo or centos.repo). Inside these files are URLs (baseurl) pointing to the official remote servers where the software is hosted.

Step 2: Resolve the Dynamic Variables
yum automatically swaps out the internal Linux variables ($releasever and $basearch) from that URL.
yum automatically reconstructs the URL into a hard internet address

Step 3: Connect to the Remote Server (The Download Source)
Your server connects out over the network to that specific web server (in this case, nginx.org or an OS mirror). It targets the RPMS/ folder on that server, which is essentially a massive online directory filled with thousands of software files.

Step 4: Download the Main Package & Dependencies
yum grabs the exact files it needs over HTTPS and downloads them. It copies down nginx-1.24.0-1.el7.ngx.x86_64.rpm (example version).
The Dependencies: It asks the remote server, "What does NGINX need to run?" The remote server replies that it needs tools like pcre and openssl. yum then pulls those .rpm files from the same server or your OS core repositories as well.

Step 5: Land in the Local Temporary Cache
The downloaded .rpm files land directly into your local storage cache at:📁 /var/cache/yum/x86_64/7/nginx/packages/

/var/cache/yum/ (or /var/cache/dnf/ on newer systems).  By default, yum automatically deletes these temporary .rpm files the moment the installation finishes to save disk space. If you want to keep them, you have to change keepcache=0 to keepcache=1 in your /etc/yum.conf file.

Step 6: Unpack, Install, and Clean Up
The system extracts the packages from the temporary cache directory and installs them to their permanent folders across the root filesystem (like /usr/sbin/nginx and /etc/nginx/). As the final step, yum deletes the temporary .rpm files from the cache directory to save your disk space.

The Executable Program  		: /usr/sbin/nginx (This is the actual binary that runs the server).
Configuration Files					: /etc/nginx/ (Where you edit nginx.conf to manage your websites).
Web Files									: /usr/share/nginx/html/ or /var/www/ (Where your default HTML web pages sit).
Logs											: /var/log/nginx/ (Where it tracks server traffic and errors).

3-Tier Architecture:
-------------------
3-tier architecture is a design pattern that divides into diff tiers of an application like presentation layer, application layer, and database layers. 
This improves scalability, security, maintainability, and availability. 
In production environments, frontend servers handle user requests, backend services process business logic, and databases manage persistent storage.”

scalability 				--> Each tier can scale independently on its own dedicated infrastructure
										Example: add more web servers,scale APIs separately,scale DB vertically
Security					--> Direct access to the database is blocked, as clients must pass through the application layer only application layer has access to database layer
Maintainability 	--> Separate teams can develop, update, or replace individual layers without breaking other parts of the system like front end and backend teams can work seperately 

1. Presentation Layer (Frontend/Web Layer) ---> This is top-most layer orusers interface where users interact with the application via a web browser or mobile app.
Examples: web UI,mobile app,React/Angular frontend,web server

Responsibilities ---> receives user requests ---> displays some default UI info ---> sends requests to backend ---> handles basic validations
Examples : nginx webserver 

Real time example: 
User opens: amazon.com
Frontend displays: -> product pages -> login page -> cart UI etc..

2. Application Layer (Business Logic Layer) ---> The middle layer that handles business logic, data processing, calculations, and command execution.
Contains: business logic,APIs,authentication,processing

Responsibilities ---> processes requests ---> validates business rules ---> communicates with DB ---> Take data from DB ---> returns responses to Presentation layer 

Component	Example
Java App	Spring Boot

Real time example: 
When user clicks: Place Order
Application layer: -> validates stock -> calculates price -> processes payment -> updates database 

3. Database Layer : The back-end layer that stores, manages, and retrieves data using database management systems or cloud storage.

Responsibilities : data storage,retrieval,transactions,backups

Examples
Database	Example
Relational	MySQL, PostgreSQL
NoSQL	MongoDB

Real-Time Example : Stores: users,orders,payments,products info/data


Full Request Flow: 
Step 1 — User Request 				--> User accesses website example.com
Step 2 — Presentation Layer 	--> Nginx/web server receives request and open basic UI page.
Step 3 — Application Layer 		--> Backend API processes logic
Step 4 — Database Layer 			--> Database stores/fetches data.
Step 5 — Response Back 			--> Response travels back to user.

Cloud Example in Amazon Web Services
Layer				AWS Service
Presentation		ALB + EC2
Application			EC2/EKS
Database			RDS




Here is how a simple action—checking your account balance—flows through the three tiers:
1. Presentation Tier (The User Interface)
What it is: The mobile banking app on your phone or the website open in your desktop browser (built using HTML, CSS, JavaScript, or React/Flutter).
What it does: It displays a clean dashboard with a button that says "View Balance".
The Action: You tap the button. The presentation tier captures this click and sends a secure HTTPS request (e.g., GET /account/balance) over the internet to the next layer.

2. Application Tier (The Logic Engine)
What it is: The backend servers running on cloud infrastructure (built using languages like Java, Python, or C#).
What it does: This layer contains the strict rules and logic of the bank.
The Action: The server receives your request and performs several checks:
		Authentication: Is this user actually logged in?
		Authorization: Does this user have permission to view this specific account?
		Processing: It formats a query to securely ask the database for the exact numbers.

3. Data Tier (The Storage)
What it is: A secure, relational database management system (like Oracle, PostgreSQL, or MySQL).
What it does: It acts as the ultimate source of truth, storing user profiles, transaction histories, and account balances.
The Action: The database receives the highly secure query from the application tier, locates your account row, pulls the figure (e.g., $1,250.00), and passes it back up to the application tier.


The Return Journey
Once the data tier provides the balance, the application tier formats it into a standard format (like JSON). 
Finally, the presentation tier receives that data and renders it beautifully on your screen so you can see your balance.

NAT(Network Address Translation) :
-----------------------------------------------  
NAT (Network Address Translation) is a networking technique that allows multiple devices on a private local network to share a single public IP address to access the internet.

How NAT Works (Step-by-Step)
The Request		: Your laptop (Private IP: 192.168.1.5) requests a webpage from Google.
The Translation	: The request hits your router. The router strips away your laptop's private IP, replaces it with your ISP-assigned Public IP (e.g., 203.0.113.1), assigns a unique port number to the request, and logs this connection in a NAT Translation Table.
The Response	: Google sends the webpage back to your router's Public IP and that specific port.
The Delivery		: The router looks at its translation table, matches the port number back to your laptop (192.168.1.5), and delivers the data.

The 3 Main Types of NAT :
1. PAT (Port Address Translation / NAT Overload):  It maps thousands of private internal IPs to one single public IP by assigning unique tracking ports to each connection.
2. Static NAT				: Maps one private IP to one permanent public IP on a 1:1 basis. This is used when an internal server (like a web server) needs to be consistently reachable from the outside world.
3. Dynamic NAT		: Maps private IPs to a pooled group of multiple public IP addresses on a first-come, first-served basis.

HTTP Status Codes :
---------------------------

| Range | Meaning       |
| ----- | ------------- |
| 1xx   | indicates Informational codes |
| 2xx   | indicates Success codes       |
| 3xx   | indicates Redirection codes  |
| 4xx   | indicates Client Errors codes|
| 5xx   | indicates Server Errors codes |

1xx — Informational codes -> Request received and continue, processing  --> Example:100	Continue
100 Continue  					-->  The server has received the request headers, and the client should proceed to send the request body
101 Switching Protocols --> The requester has asked the server to switch protocols and the server has agreed to do so.
102 Processing 				--> An interim response used to inform the client that the server has accepted the complete request but has not yet completed it
103 Early Hints 				--> Used to return some response headers before the final HTTP message.

2xx  —  indicates Success codes    
200 OK 					--> request succeessful along with data  --> Example: webpage loaded and API returned success
201 Created 			--> new resource/data created --> POST APIs
202 Accepted		--> the request is accepted and request is in (queued for background processing)
204 No Content 	--> Request successful but:❌ no response body or (success with empty response) 
206 Partial Content

3xx — Redirection Codes
Means: resource moved/redirection required.
301 Moved Permanently 			--> Used for: URL redirects --> HTTP → HTTPS redirect  or The requested resource has been assigned a new permanent URL.Any future requests should use this new URL. 
302 Found	(Moved Temporarily) --> Temporary URL redirect or  The resource is temporarily located at a different URL, but the client should continue using the original URL for future requests
304 Not Modified 			 				--> if the url is not modified same url load from Browser cache and Improves performance.
Tells the browser that the cached copy of the file it holds is still identical to the server's version. The server sends no body data, allowing the browser to load the page instantly from local storage(i.e., caching) to save bandwidth.

4xx — Client side Errors Codes --> Means: issue from client/request side
400 Bad Request 					--> Invalid request body syntax/data
401 Unauthorized 				--> Authentication required is missing.
403 Forbidden 						--> Authenticated but Access denied --> Example:permission issue and nginx restriction
404 Not Found	 					--> Requested resource/page doesn't exist
405 Method Not Allowed 	-->  Wrong HTTP method used. --> Example: if we give GET instead of POST request 
429 Too Many Requests (rate limited)


5xx — Server Side Error Codes  --> Means : the client's request is fine but Server Side failed errors issue
500 Internal Server Error --> Generic server failure  means server encountered an unexpected condition which server doesnt know how to handle the issue basically in backend application code crash/unhandled exception
502 Bad Gateway --> Usually: reverse proxy issue and backend server down and common with Nginx and Load Balancers 
		The server was acting as a gateway or proxy (like web)and received an invalid response from the upstream server(catalogue) it tried to contact. 
		This usually happens when your web server (like Nginx) is running fine, but your backend application process (like java or Node application) has completely crashed or timed out.
503 Service Unavailable --> The server is currently unable to handle the request. --> Reasons server may be: down for scheduled maintenance and overloaded with traffic  
504 Gateway Timeout --> The server was acting as a gateway or proxy(like web) and timed out waiting for a response from the upstream server(This means your backend application took too long to process the request ).  --> (e.g., a massive database query running past the allowed limit)
505 HTTP Version Not Supported: The server does not support the HTTP protocol version that was used in the request.

500 is an unhandled backend code crash
502 means the proxy is up but the backend app is completely dead/unresponsive
503 means the server is temporarily overloaded or down for maintenance
504 means the backend app is running but took too long to finish a heavy task like a slow database query.

---------------------------
An inode is a data structure in Linux filesystem that stores metadata (information) about a file or directory except the file name and actual file content.
or
Inode is a filesystem data structure that stores metadata(information) about files and directories such as permissions, ownership, size, timestamps, and disk block locations. It does not store the filename and actual file content. 
Each and every file needs one inode whether it is small or large file doesn't matter, and if inode usage reaches 100%, new files cannot be created even when disk space is available.

Real DevOps Use Cases of Soft Links ⭐⭐⭐
1. Version Switching
Example application releases:
in the below folder we store code versions currently we have 3 versions

/app/releases/
v1
v2
v3

Create symlink
ln -s /app/releases/v3 /app/current

application uses/deployed  --> /app/current      v3 is deployed

now if u want to deploy new version v4 just change the symlink

ln -sfn /app/releases/v4 /app/current     ---> now deployed/current points to version is v4 				-sfn : s - Symbolic  f - Force n - no dereference 

lets say we have an issue in version v4 i wan to rollback to previous version just

ln -sfn /app/releases/v3 /app/current

2. Nginx Configuration

example: Actual file --> /etc/nginx/sites-available/app.conf
Enable:
ln -s /etc/nginx/sites-available/app.conf /etc/nginx/sites-enabled/app.conf

To make a website live, you create a symlink of that configuration file inside /etc/nginx/sites-enabled/. 
If you ever need to take the site offline for maintenance, you just delete the symlink without losing the configuration file itself.

3. Log Management and Rotation 

An app might save its logs to a dynamic folder like /var/lib/docker/containers/xyz123/xyz123-json.log
A symlink is created at a clean, predictable path like /var/log/my-app.log pointing to that messy container path. 
Log monitoring tools (like Logstash, Fluentd, or Promtail) are then configured to watch the clean symlink path.

Hard Link vs Soft Link Deep Comparison

| Concept          | Hard Link       | Soft Link     |
| ---------------- | --------------- | ------------- |
| Points to        | inode           | filename/path |
| Inode            | Same            | Different     |
| Data             | Same data block | Reference     |
| Delete original  | Works           | Breaks        |
| Directory link   | No              | Yes           |
| Cross filesystem | No              | Yes           |
| Storage          | No duplicate    | Very small    |
| Command          | ln              | ln -s         |


Troubleshooting Commands

Find inode: ls -li
Find hard links: find / -inum 12345

Example:
find / -samefile app.log
Find soft links: find / -type l


Hard links create another file entry pointing to the same inode and same data blocks, so deleting one filename does not remove the data until all hard links are deleted. 
Soft links are separate files with their own inode that store the path of another file. They are mainly used for shortcuts, application version switching, and configuration management.

sort	: 	Arrange file content in alphabetical or numerical order.
-------
ex: 
cat names.txt
names.txt has content like 
		ramesh
		arun
		suresh
		mahesh

cmd : sort names.txt     ---> sort all names in files in an alphabetical order a-z/A-Z and it is only shown as temporarily if u want to save in that alphabetical format use -o 
o/p:
		arun
		mahesh
		ramesh
		suresh

Reverse Sorting (z-a)

sort -r names.txt  --> same values above printed like backward    suresh ramesh mahesh arun\

Numeric Sorting
Ex : file has data 
		10
		5
		100
		20
normal sort :  sort numbers.txt
	10
	100
	20
	5           --> because it sorts like text 
correct way:
sort -n numbers.txt
o/p:
5
10
20
100

Sort and Save Output --> sort names.txt -o names.txt

Sort by Column
employees.txt below content present
Arun 50000
Ramesh 40000
Suresh 60000

Sort by salary:
sort -k2 employees.txt


uniq :
--------
Remove/counts or display duplicate adjacent lines.

Example:
1)
cat names.txt
content:
arun
arun
ramesh
suresh
suresh

uniq names.txt   --> remove duplicate names
o/p:
arun
ramesh
suresh

2)important: uniq removes only nearby duplicates means 
only deletes this side by side:
arun
arun
ramesh
suresh
suresh

it will not delete if data is like below
arun
ramesh
arun
suresh

for that we can use sort option it will sort the data like above nearby and give o/p to uniq

sort file.txt | uniq 

now o/p:
arun
ramesh
suresh

Count Duplicate Lines     --> sort file.txt | uniq -c
Show Only Duplicate Lines --> uniq -d file.txt
Show Only Unique Lines    --> uniq -u file.txt

WC(word count) :    Used to count lines,words,characters,bytes
------------------------
ex:
cat users.txt

content:

Arun DevOps
Ramesh AWS
Suresh Linux

command :
wc users.txt --> o/p: 3 6 32 users.txt
means 
3  → lines
6  → words
32 → bytes

wc -l users.txt   	--> Count only lines
wc -w users.txt   	--> Count only words
wc -m users.txt   	--> Count characters
wc -c users.txt   	--> Count bytes

ex:  cat /etc/passwd | wc -l

tar(Tape Archive) :  It is used to Combine multiple files/directories into a single archive file.
------------------------
imp :  tar alone does not compress.

example : we have a directory called /app in that we have diff files
/app

file1.txt
file2.txt
logs/

Create tar archive   ---> tar -cvf app.tar /app   -->  it creates app.tar

-c = create
-v = verbose(show files)
-f = filename

Extract tar file --> tar -xvf app.tar     --> -x = extract
View tar content --> tar -tvf app.tar

tar with compression (.tar.gz)
ex: tar -czvf app.tar.gz /app
-c create
-z gzip compress
-v show process
-f filename

Extract tar.gz
tar -xzvf app.tar.gz

Real example:
-------------
Backup : tar -czvf backup.tar.gz /var/log
Restore: tar -xzvf backup.tar.gz

Zip : used to Compress files/directories into .zip archive.
-----
Eample:
1)Compress single file ---> zip app.zip app.log
before : app.log After : app.log and app.zip --> original remains 
2)Compress directory
     zip -r app.zip /app       --> recursive means include inside files also
Extract zip ---> unzip app.zip

ex: unzip -o app.zip --> -o : overwrite old files 


gzip : gzip compresses files using gzip algorithm. mostly used for logs and backups
-----
ex:
1)gzip app.log --> creates app.log.gz file and Original file removed (i.e., app.log)

2)To Keep original file 
gzip -k app.log
now :
app.log
app.log.gz

Extract gzip ---> gunzip app.log.gz o/p : app.log

tar vs zip vs gzip

Very important interview question.

| Feature | tar | zip | gzip |
|-|-|-|
| Archive multiple files | Yes | Yes | No(single file) |
| Compression | No by default | Yes | Yes |
| Original removed | No | No | Yes |
| Extension | .tar | .zip | .gz |


Common DevOps Usage
--------------------
Application backup : tar -czvf app-backup.tar.gz /app
Compress logs      :gzip application.log
Package code	   :zip -r code.zip project/
View large logs    : more /var/log/messages
Count errors       : grep ERROR app.log | wc -l

Interview Short Answer:
------------------------
wc     → count lines, words, bytes
more   → read large files page wise
tar    → archive multiple files/directories
zip    → archive + compress files into .zip
gzip   → compress single file into .gzDevops
