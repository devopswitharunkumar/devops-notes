SSH stands for Secure Shell.
It is a secure way to connect remotely from one server to another server over a network or internet.
or 
“SSH is a secure protocol used to remotely connect and manage servers over an encrypted network connection.”

1)ssh key-gen -f <filename> --> it will generate the public key and privatekey
2)ssh-rsa <publickey code> <laptopname> -->This line tells the server: “Allow the owner of the matching private key to authenticate/login.”

We use ssh-rsa public keys for secure passwordless SSH authentication.
When SSH connection starts, the server verifies the matching private key before allowing access.”
SSH creates an encrypted tunnel so nobody can easily read the data.

ssh username@server-ip

What Happens Internally:
-----------------------
1)SSH client starts connection on your machine
2)Server checks identity i.e public keys
3)Authentication happens --Server sends encrypted challenge.
4)Secure encrypted connection is established -- when private key matches public key(✅ Authentication successful)
5)Terminal access opens -- You get terminal access to server.
Types:
------
1)Password Authentication
ssh user@ipaddress  --> prompt for password u have to enter 
2)SSH Key Authentication 
ssh -i privatekey.pem ec2-user@<public ip>

default ssh port is ---> 22

3)ssh -i <private key> <user@private ip address> -->is used to securely connect to a remote server using SSH key-based authentication instead of passwords.”

Step 1 — SSH Client Starts --> Your laptop starts SSH program. it reads private key
Step 2 — Connection to Server --> connects/verify to -> 54.23.11.90 and prot -22((default SSH port))
Step 3 — Server Sends Challenge --> server says “Prove you own the matching private key.”
Step 4 — Private Key Verification --> my laptop use - mykey.pem (to generate encrypted response.)
Step 5 — Server Checks Public Key --> Server already has matching public key inside:(ssh-rsa cmd)-- if succeeds --> ✅ Authentication successful
Step 6 — Secure Session Created --> Encrypted SSH tunnel established --> You get terminal access.

------------------------------

Write	   	  w		Modify content
Execute	      x		Run file/script

Category	  Meaning
----------------------
User (u)	File owner

Others (o)	Everyone else

if permissions starts with

l => symlink

numeric way:
------------
4--> read
2--> write 
1--> execute

Group  = r-x = 4+0+1 = 5
Others = r-x = 4+0+1 = 5

3-Tier Architecture:
-------------------
“3-tier architecture separates an application into presentation, application, and database layers. This improves scalability, security, maintainability, and availability. In production environments, frontend servers handle user requests, backend services process business logic, and databases manage persistent storage.”


1. Presentation Layer (Frontend/Web Layer) ---> This is the layer users interact with.
Examples: web UI,mobile app,React/Angular frontend,web server

Responsibilities ---> receives user requests -> displays UI -> sends requests to backend -> handles basic validations
Examples
nginx webserver

Real time example: 
User opens: amazon.com
Frontend displays: -> product pages -> login page -> cart UI etc..

2. Application Layer (Business Logic Layer) ---> This is the core backend layer.
Contains: business logic,APIs,authentication,processing

Responsibilities ---> processes requests,validates business rules,communicates with DB,returns responses

Component	Example
Java App	Spring Boot

Real time example: 
When user clicks: Place Order
Application layer: -> validates stock -> calculates price -> processes payment -> updates database 

3. Database Layer : Stores application data.

Responsibilities
data storage,retrieval,transactions,backups

Examples
Database	Example
Relational	MySQL, PostgreSQL
NoSQL	MongoDB

Real-Time Example : Stores: users,orders,payments,products info/data


Full Request Flow: 
Step 1 — User Request

User accesses website.

Step 2 — Presentation Layer

Nginx/web server receives request.

Step 3 — Application Layer

Backend API processes logic.

Step 4 — Database Layer

Database stores/fetches data.

Step 5 — Response Back

Response travels back to user.

Why 3-Tier Architecture Is Important

1. Scalability --> Each layer can scale independently.
Example: add more web servers,scale APIs separately,scale DB vertically

2. Security --> Database not directly exposed to usersand Only application layer accesses DB

3. Maintainability --> Frontend/backend teams can work separately.

4. High Availability --> Layers can be deployed independently.

Example: Frontend,Backend,Payment,Login,Orders,Inventory

All together in one app.

Single Application

Problems

If one module crashes - entire app may crash - Scaling is difficult - Deployments are harder.

Microservices Architecture

Application divided into smaller services.

Example: Login Service,Payment Service,Product Service,Order Service

Each independent.

Diagram

  |

  |

Better Fault Isolation - Payment failure won’t crash login service.

✅ request successful --> 200 OK -->Meaning: request succeeded --> Example: webpage loaded and API returned success
201 Created --> ✅ new resource created --> POST APIs
204 No Content --> Request successful but:❌ no response body

3xx — Redirection Codes
Means: resource moved/redirection required.
301 Moved Permanently --> Used for: URL redirects --> HTTP → HTTPS redirect 
302 Found --> Temporary redirect.
304 Not Modified --> Browser cache used. and Improves performance.

4xx — Client Error Codes
Means: issue from client/request side
400 Bad Request --> Invalid request syntax/data.
401 Unauthorized --> Authentication required.
403 Forbidden --> Access denied. --> Example:permission issue and nginx restriction
404 Not Found --> Requested resource/page missing.
405 Method Not Allowed -->  Wrong HTTP method used. --> Example:GET instead of POST


5xx — Server Error Codes 
Means:server-side issue
500 Internal Server Error --> Generic server failure.
502 Bad Gateway --> Usually: reverse proxy issue and backend server down and common with Nginx and Load Balancers 
503 Service Unavailable --> Server temporarily unavailable. --> Reasons: maintenance and overload 
504 Gateway Timeout --> Backend response timeout --> reasons : microservices and load balancers

curl -I http://server-ip   --> HTTP/1.1 200 OK

Inode (Index node):
------
An inode is a fundamental data structure in Linux filesystem that stores metadata (information) about a file or directory except the file name and actual file content.
or
Inode is a filesystem data structure that stores metadata about files such as permissions, ownership, size, timestamps, and disk block locations. It does not store the filename or actual data/file content. Each/every file needs one inode whether it is small or large file doesn't matter, and if inode usage reaches 100%, new files cannot be created even when disk space is available.



information inode stores :
| Stores              | Example               |
| ------------------- | --------------------- |
| File type           | file/directory        |
| Permissions         | rw-r--r--             |
| Owner               | ec2-user              |
| Group               | devops                |
| File size           | 10 KB                 |
| Timestamps          | created/modified time |
| Link count          | hard links            |
| Disk block location | where data exists     |

Hard link and Soft link:
------------------------
A hard link creates another file/filename pointing to the same inode, so data remains accessible even if the original file is removed. 
A soft link or symbolic link is a shortcut pointing to another filename and has a different inode; it breaks if the original file is deleted.

Hard link:
-----------
A hard link is Another filename pointing to the SAME inode and SAME data blocks.
or 
Creating another filename that points to the same inode of an existing file.

Example:

now creating hard link with below command

tar vs zip vs gzip

Very important interview question.

| Feature | tar | zip | gzip |
|-|-|-|

| Compression | No by default | Yes | Yes |
| Original removed | No | No | Yes |
| Extension | .tar | .zip | .gz |
