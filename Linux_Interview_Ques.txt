## 1. Linux Boot Process

**Q1. Explain Linux boot process.**

**Answer:**

Flow:

```
BIOS/UEFI
   ↓
Boot Loader (GRUB2)
   ↓
Kernel
   ↓
initramfs
   ↓
systemd (PID 1)
   ↓
Targets
   ↓
Services
```

* **BIOS/UEFI** → hardware initialization
* **GRUB** → loads kernel
* **Kernel** → initializes hardware/drivers
* **initramfs** → temporary filesystem
* **systemd** → starts services

Check PID 1:

```bash
ps -p 1
```

# 3. Difference between soft link and hard link

| Hard Link                    | Soft Link                  |
| ---------------------------- | -------------------------- |
| Points inode                 | Points filename            |
| Cannot cross filesystem      | Can cross filesystem       |
| Works after original deleted | Breaks if original deleted |

Commands:

Hard link:

```bash
ln file1 file2
```

Soft link:

```bash
ln -s file1 file2
```

Check inode:

```bash
ls -li
```

# 5. Difference between kill and kill -9?

### kill

```bash
kill PID
```

* Sends SIGTERM (15)
* Graceful shutdown
* Process can cleanup

### kill -9

```bash
kill -9 PID
```

* Sends SIGKILL
* Immediate termination
* Cannot be ignored


# 11. Difference between TCP and UDP?

TCP:

* Connection based
* Reliable
* Acknowledgement
* Example:

  * SSH
  * HTTP
  * HTTPS

UDP:

* Connectionless
* Faster
* No guarantee
* Example:

  * DNS
  * Streaming

# 12. Explain Linux permissions

Example:

```
-rwxr-xr--
```

Meaning:

```
owner → rwx
group → r-x
others → r--
```

Numbers:

```
r = 4
w = 2
x = 1
```

Example:

```bash
chmod 755 file
```

means:

owner = 7 rwx
group = 5 r-x
others = 5 r-x

# 1. EC2 CPU is 100%. How will you troubleshoot?

### Answer:

First I check whether CPU spike is temporary or continuous.

### Step 1: Check CPU usage

```bash
top
```

or

```bash
htop
```

Check:

* CPU %
* Process ID
* User
* Command

Example:

```
PID     CPU     COMMAND

2345    95%     java
```

---

### Step 2: Check system load

```bash
uptime
```

Output:

```
load average: 8.5 7.3 6.9
```

Compare with CPU cores:

```bash
nproc
```

If:

```
CPU cores = 4
Load = 8
```

Server overloaded.

---

### Step 3: Find top CPU process

```bash
ps -eo pid,user,%cpu,%mem,cmd --sort=-%cpu | head
```

---

### Step 4: Analyze process

For Java:

```bash
jstack PID
```

Check threads.

For Linux process:

```bash
strace -p PID
```

---

### Step 5: AWS side checks

Check CloudWatch:

* CPUUtilization
* CPU Credit balance (T2/T3)
* Auto Scaling activity

Check instance type.

---

### Fix:

Depends on issue:

* Restart bad process

```bash
systemctl restart service
```

* Scale EC2
* Add Auto Scaling
* Optimize application

---

# 2. Nginx 502 Bad Gateway issue

### What is 502?

Nginx is working but backend application is not responding.

Flow:

```
User
 |
Nginx
 |
Backend App
```

---

### Step 1: Check nginx status

```bash
systemctl status nginx
```

---

### Step 2: Check nginx logs

Ubuntu:

```bash
tail -f /var/log/nginx/error.log
```

RHEL:

```bash
tail -f /var/log/nginx/error.log
```

Example:

```
connection refused upstream
```

---

### Step 3: Check backend service

Example:

```bash
systemctl status tomcat
```

or

```bash
systemctl status nodeapp
```

---

### Step 4: Check backend port

Example backend runs 8080:

```bash
netstat -tulnp | grep 8080
```

or

```bash
ss -tulnp
```

---

### Step 5: Test locally

```bash
curl localhost:8080
```

---

### Causes:

* Application down
* Wrong upstream config
* Firewall issue
* Timeout issue

# 4. Disk full but df and du mismatch

Scenario:

```bash
df -h
```

shows:

```
/dev/xvda 100%
```

but:

```bash
du -sh /*
```

shows less usage.

---

### Reason:

Deleted files still held by running process.

Example:

Application writes log:

```
app.log 50GB
```

Someone deletes:

```bash
rm app.log
```

but app still holds file handle.

---

### Find:

```bash
lsof | grep deleted
```

Example:

```
java 1234 deleted app.log
```

---

### Fix:

Restart process:

```bash
systemctl restart app
```

or kill PID:

```bash
kill PID
```

# 6. Load average high but CPU normal

Example:

```bash
uptime
```

shows:

```
load average: 20
```

but CPU:

```
20%
```

---

Meaning:

Processes are waiting, not running.

Usually:

* Disk I/O issue
* Network storage delay

---

### Check IO wait

```bash
top
```

Look:

```
%wa
```

High wa = disk issue.

---

Check disk:

```bash
iostat -xz 2
```

Install:

```bash
yum install sysstat
```

---

Find processes:

```bash
ps aux | awk '$8=="D"'
```

D = waiting for IO

---

Fix:

* Optimize disk
* Increase EBS IOPS
* Check database queries

# 8. File descriptor limit issue

Error:

```
Too many open files
```

---

### Check current limit

```bash
ulimit -n
```

Example:

```
1024
```

---

### Check process open files

```bash
lsof -p PID | wc -l
```

---

### Increase temporary:

```bash
ulimit -n 65535
```

---

### Permanent change:

Edit:

```bash
vim /etc/security/limits.conf
```

Add:

```
appuser soft nofile 65535
appuser hard nofile 65535
```

For systemd:

```bash
vim /etc/systemd/system/app.service
```

Add:

```
LimitNOFILE=65535
```

Reload:

```bash
systemctl daemon-reload
systemctl restart app
```
