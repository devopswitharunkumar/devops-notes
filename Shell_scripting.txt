Shell :
--------
Shell is a command-line interpreter that acts as a bridge/interface between the user and the kernel(i.e., OS). It receives commands from the terminal entered by users,  interprets them and executes them into instructions/programs or operations that the operating system. shell provides a way for users to interact with the operating system using commands. Without the shell, the system cannot understand human-readable commands

Basically Interprets and validates user commands and Converts commands into system calls and Executes built-in and external programs and Displays output or error messages on terminal and Provides scripting capabilities

Shell Scripting :
--------------------
Shell scripting allows users to combine/write multiple commands into a single file and execute them as a program, enabling structured task automation and system control.
or
A shell script is essentially a text file containing a series of commands that the shell can interpret and execute with extension .sh

It is widely used in DevOps for automation tasks such as deployments, monitoring, backups, service management, and infrastructure administration.

advantages : Automate Repetitive Tasks

| Benefit        | Explanation                |
| -------------- | -------------------------- |
| Automation     | Reduces manual work        |
| Fast execution | Commands run automatically |
| Reusability    | Reuse scripts              |
| Consistency    | Avoid human mistakes       |

Exit status :
---------------
In shell script if command fails it does not automatically terminate the script by default Bash continues executing the next command

It returns the exit status of the previous command whether it is successful or not --> 
0 			--> success and 
1-255  --> any number in between is failure/error and Different numbers point to different types of errors
1  	 	--> General Error
126 	--> Command found, but cannot be executed
127 	--> Command not execute
130 	--> terminated by user
$? --> contains the exit status of the most recently executed command
Every linux command or script sends back the status to operating system when it finishes the running 
exit 1   --> Terminate the current script immediately and return exit status 1 to the calling process/operating system.

output redirections :
---------------------------
in shell script by default logs will not be recoded/stored when u run the command whether it is success or failure 

1 -- success log will be stored 		-- stdout
2 -- failure log will be stored 			-- stderr 
& -- both success and failure logs will be reditrected to a log file		-- both stdout and stderr 

Examples :
yum install git 1> success.log or yum install git > success.log 			-->  only stored success message(stdout) if installation failed log not recoreded  1 or nothing we can give
yum install mysql 2> error.log 																-->  only stored failed message if installation success log not recoreded
yum install git &> successanderror.log 												--> both success logs and error logs stored 

> and >> diff :
yum install mysql 1> temp.log
yum install git 1> temp.log          --> only git logs will be there because when u run two commands > because of this symbol mysql logs overwritten by git logs
In above two commands first command stores the successful logs of mysql and when u run 2nd command that is git . Git logs will replaces the mysal logs because we used '>' it will remove existing content/logs and replace new logs 

to skip above scenario we have an option called  --->    >> append  
yum install mysql 1>> temp.log
yum install git 1>> temp.log      --> now both mysql and git sucees logs will be there because after mysql logs 2nd commnd logs will append the existing content  

log file name --> <scriptname>-date.log

Redirections :
------------------
>		Redirects stdout to a file (overwrite)		1 or > both are same 
							Ex :  ls > success.txt  or sh file.sh > output.txt
>>	Redirects stdout to a file (append)
							Ex : command >> success.txt
2>	Redirects stderr to a file (overwrite)
							Ex : command 2> err.txt
2>>	Redirects stderr to a file (append)
							Ex  : command 2>> err.txt
&>	Redirects both stdout and stderr to the same file
							Ex : command &> succand err.txt
							
2>&1	Redirects stderr to stdout (combines both outputs)
Ex : 

1. Redirecting stdout and stderr to the Same File 
	Method 1 : command > output.txt 2>&1
		 > -- first redirects stdout to output.txt (that is 1's logs), creating the file if it doesn't exist or if exists overwriting existing content
		2>&1 then redirects stderr(2's logs) to where stdout is currently redirected (output.txt).

	Method 2: Using &> :	command &> output.txt
		 it will redirect both stdout and stderr to the same file and it may not work with older linux distributions like sh 

	Appending stdout and stderr to an Existing File
				Ex : command >> output.txt 2>&1

2. Redirecting stdout and stderr to Separate Files
		Ex : command > output.txt 2> error.txt				--> > sends stdout to output.txt and 2> sends stderr to error.txt
		
3. By default, when you redirect output, you see nothing in the terminal. If you want to see the output in terminal and save it to a file at a time 
	1. sh 02-variables.sh | tee out.log   					--> saves output to out.log and displays on the terminal -- overwrites the logs if file already exists 
	2. sh 02-variables.sh | tee -a out.log				--> append the output to a existing file content
	3. sh 02-variables.sh 2>&1 | tee output.txt	--> both stderr and stdout

Date Formats : 
-------------------
YYYY-MM-DD		date +"%Y-%m-%d"			or %F

• %Y : 4-digit year (e.g., 2026)
• %y : 2-digit year (e.g., 26)

• %m : Month as a number (01 to 12)
• %B : Full month name (e.g., September)
• %b / %h : Abbreviated month name (e.g., Sep)

• %d : Day of the month (01 to 31)
• %A : Full weekday name (e.g., Wednesday)
• %a : Abbreviated weekday name (e.g., Wed)

• %H : Hour in 24-hour format (00 to 23)
• %M : Minute (00 to 59)
• %S : Second (00 to 59)
• %Z : Alphabetic timezone abbreviation (e.g., EST)

Disk is attached to Ec2 but To get that disk into usag. we need to create file system first
2)sudo file -s /dev/xvdf     --> Check whether a filesystem exists	
			If no filesystem exists: /dev/xvdf: data 
			If an XFS filesystem exists:  /dev/xvdf: SGI XFS filesystem data
3)sudo mkfs -t xfs /dev/xvdf		--> Create a filesystem
					Creates an XFS filesystem on the disk so Linux can store and manage files on it
					mkfs – Make filesystem.
					-t xfs – Specify XFS filesystem type.
					 /dev/xvdf – Target disk.

6)df -hT 	--> verify the mount 		--> Now you can see /dev/xvdf mounted on /data.

Does mounting persist after an EC2 reboot  --> No 
A manual mount using --> sudo mount /dev/xvdf /data -->  does not automatically persist across reboots.


So To attach permanently, configure /etc/fstab using filesystem UUID 
sudo blkid /dev/xvdf		--> get the UUID 
UUID=1234-abcd  /data  xfs  defaults,nofail  0  2
or
1. sudo blkid /dev/xvdf
2. sudo vi /etc/fstab		--> Edit the filesystem table:
Add your UUID entry and save
3. sudo mount -a 

/etc/fstab --> /etc/fstab stands for Filesystem Table.
					It is a Linux configuration file that tells the operating system which disks/filesystems should be mounted automatically during boo

Interview-ready explanation
When we attach an EBS volume to an EC2 instance, 
first I log in to the instance and use lsblk to verify the newly attached disk. 
Then I use file -s to check whether a filesystem already exists. 
If it is a new empty disk, I create an XFS filesystem using mkfs -t xfs. Next, I create a mount point such as /data and mount the EBS volume using the mount command. 
I verify it using df -hT. Finally, I configure /etc/fstab with the filesystem UUID to ensure the mount persists after an EC2 reboot."

    echo "Instance is : $i"
    if [ $i == "mongodb" ] || [ $i == "mysql" ] || [ $i == "shipping" ]
then
    INSTANCE_TYPE="t3.small"
else
    INSTANCE_TYPE="t3.micro"
fi
    IP_ADDRESS=$(aws ec2 run-instances --region us-east-1 --image-id $AMI_ID --instance-type $INSTANCE_TYPE --security-group-ids $SG_ID --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=$i}]" --query "$(VALIDATE)" --output text)

    echo "$i : $IP_ADDRESS"


# Creates route 53 records based on env name

    aws route53 change-resource-record-sets \
    --hosted-zone-id $HOSTED_ZONE_ID \
    --change-batch '
    {
        "Comment": "creating a route53 record"
        ,"Changes": [{
        "Action"              : "UPSERT"
        ,"ResourceRecordSet"  : {
            "Name"              : "'$i'.'$DOMAIN_NAME'"
            ,"Type"             : "A"
            ,"TTL"              : 1
            ,"ResourceRecords"  : [{
                "Value"         : "'$IP_ADDRESS'"
            }]
        }
        }]
    }
    '

done
